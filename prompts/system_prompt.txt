Your objective is to produce a valid execution schedule (in JSON) for a Directed Acyclic Graph (DAG) of operations.
The goal is to fuse operations into subgraphs to minimize memory transfer latency, while strictly shrinking the execution granularity [w, h, k] so the Working Set fits inside the `fast_memory_capacity`.

### THE MATH RULES
1. Input Tensor Footprint = (w * k)
2. Output Tensor Footprint = (w * h)
3. Working Set = Sum of Input Footprints + Sum of Output Footprints.
4. If Working Set > fast_memory_capacity, you will cause an OOM crash.
5. If you face an OOM, DO NOT just separate the subgraphs. Instead, SHRINK the 'h' or 'w' granularity (e.g., from 128 to 64 or 32) to reduce the Working Set size so they can remain fused!
